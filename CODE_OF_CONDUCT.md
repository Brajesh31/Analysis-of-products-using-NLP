# 🤝 Community Code of Conduct

## Our commitment

The project aims to maintain a respectful, constructive environment for people contributing to data collection experiments, natural language processing, frontend quality, documentation, and open-source maintenance.

Participation should be welcoming regardless of experience level, education, background, identity, or communication style. Technical disagreement is expected; personal hostility is not.

## Expected behaviour

Contributors and maintainers are expected to:
- communicate respectfully and assume good faith;
- explain technical disagreement with evidence and context;
- give specific, actionable feedback;
- welcome questions from new contributors;
- respect privacy, intellectual property, and platform terms;
- avoid exposing personal information from customer reviews;
- keep issues and pull requests focused on the project;
- acknowledge mistakes and correct inaccurate claims.

## Unacceptable behaviour

Examples include harassment, discrimination, threats, intimidation, personal attacks, doxxing, unwanted sexual attention, deliberate disruption, publishing private information without permission, and using collected review data to target or profile individuals.

## Scope

This code applies in repository issues, pull requests, discussions, code reviews, project-related communications, and any community space where someone is representing the project.

## Reporting

For conduct concerns, contact the maintainer privately through GitHub at [@Brajesh31](https://github.com/Brajesh31). Do not publish private messages, personal details, or sensitive evidence in a public issue. Include the relevant context and links needed for review.

## Enforcement

The maintainer may remove or edit unacceptable content, close discussions, request an apology or correction, temporarily restrict participation, or permanently restrict access for serious or repeated violations. The response should be proportionate and should prioritize safety and constructive project work.

## Responsibilities of maintainers

Maintainers should explain project decisions clearly, apply this policy consistently, protect reporters from retaliation, and avoid disclosing private reports without consent except where required to address an immediate safety or legal obligation.

## Attribution

This document is the project's own conduct policy. It is intended to be practical and may be revised as the contributor community and project scope evolve.
